# Участник 1: требования после аудита

Раздел 5.2 [плана разработки](../../DEVELOPMENT_PLAN.md), пункты **1.H1–1.H3**. Изменения относятся к интерфейсу бизнеса. Формула рейтинга и серверные правила подтверждения остаются прежними.

## 1.H1 — публичный предпросмотр

- Предпросмотр использует сохранённую задачу и подтверждения, полученные с сервера. Только отмеченная в форме галочка ещё не добавляет сведения в публикацию.
- Несохранённые изменения сопровождаются пояснением: сначала сохранить и подтвердить, затем публиковать.
- Полностью пустую публикацию интерфейс останавливает с подсказкой. Текст и отметки остаются в форме.
- Рейтинг не ограничивает публикацию. Достаточно любого непустого подтверждённого поля; например, название можно опубликовать с 0 баллов.
- Экран успеха использует только `publishedVersion`, включая название, балл и сведения. Неподтверждённое название черновика не подставляется.
- Старый пустой публичный снимок открывается для исправления, без сообщения об успешной публикации.

### Интеграция с участником 2

Пункт **2.H1 реализован сервером** в коммите `4a0fe61`. При пустом подтверждённом снимке фактический контракт отличается от первоначального предложения `422 / empty_publication`:

```http
HTTP/1.1 400 Bad Request
```

```json
{
  "detail": "Подтвердите хотя бы одно заполненное поле перед публикацией."
}
```

Сервер отклоняет пустой снимок внутри транзакции до его записи, сохраняя прежние публикацию и версию. Конфликт версии по-прежнему возвращает `409`. Общий клиент извлекает строку `detail`, а интерфейс показывает её без очистки формы; отдельный обработчик предполагаемого `422 / empty_publication` удалён. Публикация непустого подтверждённого поля с 0 баллов разрешена. Серверная зависимость закрыта; полный совместный прогон `ALL.H1` остаётся отдельным пунктом.

После подключения `4a0fe61` выполнен статический review транзакции, обработки HTTP 400 и привязок всех 12 резервных вопросов к полям интерфейса: несовместимостей не обнаружено. Предпросмотр перезапущен с прежней отдельной демобазой и `.env`. В Edge для слабого описания показаны три новые формулировки с правильными назначениями «Потребность», «Пользователи» и «Данные». Автоматические тесты и полный совместный сценарий в этом проходе не повторялись; результаты 20 core и 5 marketplace-тестов относятся к [проходу участника 2](../../docs/PARTICIPANT_2.md).

## 1.H2 — подсказки качества

Отдельный модуль `text-quality.js` предлагает уточнить точные ответы вроде «не знаю», одну букву или знаки вместо описательного ответа. Короткие темы, контакты, числа и содержательное «нет» не отвергаются по длине.

У критерия успеха есть явно обозначенный пример измеримой метрики. Подсказки не заполняют поля, не меняют подтверждения, не блокируют сохранение и не начисляют баллы.

## 1.H3 — исходное описание рядом с карточкой

Редактор показывает исходный текст рядом с текущими полями, а на узком экране — над ними. Для сохранённой задачи используется `rawDescription` сервера. Дополнительного AI-запроса и выдуманной истории изменения рейтинга нет.

Статический review выявил и исправил устаревание предпросмотра при успешном сохранении и последующей ошибке подтверждения. Обновляется только предпросмотр, без замены введённых значений и галочек. Также исправлен внешний заголовок экрана успеха: он больше не подставляет название черновика.

Автоматические тесты в этом проходе не добавлялись и не запускались. `node --check` не выполнен: Node отсутствует в доступном `PATH`; модули успешно загрузились в Edge. `git diff --check` выполнен без ошибок. Отказ подтверждения после частичного сохранения и старый пустой снимок рассмотрены по коду; отдельного воспроизведения этих сценариев в браузере не было. На момент этого браузерного прохода серверная проверка ещё отсутствовала; её последующее подключение в `4a0fe61` отражено в разделе интеграции выше. Общая приёмка **ALL.H1** остаётся открытой.
