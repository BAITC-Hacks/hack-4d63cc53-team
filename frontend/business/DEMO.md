# Участник 1: создание и улучшение карточки за 90 секунд

Личная часть шага 1.7: первые **0:00–1:30** общей демонстрации до пяти минут из [плана разработки](../../DEVELOPMENT_PLAN.md). Цель — показать путь от короткого описания до сохранённой карточки с подтверждёнными сведениями и передать её участнику 2 с рейтингом **50/100**.

Сценарий соответствует текущим кнопкам интерфейса и резервному анализу. Все сведения о кафе синтетические. Результаты браузерной приёмки предыдущего шага — в [ACCEPTANCE.md](ACCEPTANCE.md).

Доработки после аудита: исходное описание видно рядом с редактором, мягкие подсказки помогают уточнять формальные ответы, а блок «Что увидят команды» показывает сохранённые подтверждённые сведения. Перед передачей публикации участнику 2 покажите этот предпросмотр: новые галочки попадут в него только после сохранения подтверждений. Пустую публикацию останавливают интерфейс и сервер; рейтинг 0 сам по себе допустим. Результаты и контракт интеграции — в [REQUIREMENTS.md](REQUIREMENTS.md).

## Подготовка до выступления

Команды выполняются из корня репозитория с уже установленными зависимостями и существующей `.venv`. Порт 8000 должен быть свободен. Корневой `.env` оставьте без изменений.

1. Создайте отдельный набор демоданных в **новом** файле базы:

   ```powershell
   .\.venv\Scripts\python.exe -m data.seed_demo --database backend/runtime/demo-new.sqlite3
   ```

   Загрузчик откажет, если файл уже существует. Для следующей репетиции выберите новое имя файла, например `demo-rehearsal-2.sqlite3`; прежняя база сохранится.

2. Создайте отдельный файл `.env.demo` в корне репозитория со следующим содержимым:

   ```dotenv
   AI_MODE=fallback
   OPENAI_API_KEY=
   DATABASE_PATH=backend/runtime/demo-new.sqlite3
   ```

   Путь `DATABASE_PATH` должен совпадать с путём, переданным загрузчику. Все настройки запуска задаются `.env.demo`, который уже исключён из Git правилом `.env.*`. Используйте новый терминал без ранее заданных переменных проекта: переменные процесса имеют приоритет над файлом.

3. Запустите сервер с отдельным файлом настроек:

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --env-file .env.demo
   ```

4. Откройте `http://127.0.0.1:8000/`. Выберите роль **«Бизнес»**, проверьте **«Подключено к серверу»**. Держите готовые тексты из следующего раздела рядом с окном приложения. После выступления остановите сервер сочетанием `Ctrl+C`.

Seed создаёт исходные задачи, команды и отклики. В личной части участника 1 создаётся **новая** карточка «Демо: очередь в кафе», чтобы её исходное состояние не зависело от seed. Для общего продолжения участникам 2 и 3 нужно заранее согласовать работу именно с этой карточкой: отклики seed относятся к исходным задачам и автоматически к ней не переносятся.

## Данные для копирования

### Исходное описание

```text
Хотим сократить очереди в кафе
```

### Ответы на три вопроса

В режиме `fallback` при доступном сервере вопросы относятся к потребности, пользователям и данным. Проверьте значение **«Сохранить ответ в поле»** перед переходом к карточке.

| Поле назначения | Ответ |
|---|---|
| Потребность | Сократить время ожидания заказа в обед |
| Пользователи | Гости и кассиры кафе, будни 12:00–14:00 |
| Данные | Обезличенные времена заказов за две недели |

### Дополнение в редакторе

| Поле | Значение |
|---|---|
| Тема | Кафе |
| Название | Демо: очередь в кафе |
| Контекст | Хотим сократить очереди в кафе |

Контекст заполняется исходным описанием автоматически; проверьте его. Остальные шесть полей пока оставьте пустыми.

## Действия по таймеру

Это целевой тайминг, результат фактической репетиции фиксируется отдельно ниже.

| Время | Действие в интерфейсе | Что должно быть видно |
|---|---|---|
| 0:00–0:15 | Нажать **«Создать задачу»**, вставить исходное описание | Короткая бизнес-идея без подробностей |
| 0:15–0:30 | Нажать **«Проанализировать»**; показать три вопроса и отметку **«Резервный AI-режим»** | Вопросы о потребности, пользователях и данных |
| 0:30–0:50 | Вставить три ответа, проверить поля назначения; нажать **«Перейти к карточке»** | Ответы перенесены в соответствующие поля |
| 0:50–1:05 | Заполнить тему и название, показать редактируемый контекст | Шесть заполненных полей, остальные пустые |
| 1:05–1:15 | Без отметок подтверждения нажать **«Создать черновик»** | Карточка сохранена, рейтинг **0/100** |
| 1:15–1:25 | Отметить **«Подтверждаю»** у темы, названия, контекста, потребности, пользователей и данных; нажать **«Сохранить и пересчитать»** | Рейтинг **50/100**, расшифровка и недостающие сведения |
| 1:25–1:30 | Оставить редактор открытым и передать слово участнику 2 | Та же сохранённая карточка готова к дополнению |

Рейтинг 50 складывается из трёх групп: **контекст и потребность — 20, данные — 20, пользователи — 10**. Тема и название подтверждаются для публикации, отдельного веса в рейтинге у них нет. Пустые поля не подтверждайте. Изменение уже подтверждённого текста снимает его подтверждение.

## Короткий текст речи

> У кафе есть короткая идея: хотим сократить очереди. Для команды этого мало: пока непонятно, кто сталкивается с проблемой и какие данные доступны. Я создаю задачу и запускаю анализ. Сегодня включён резервный режим, это явно указано на экране. Получаем три уточняющих вопроса. Вставляю подготовленные ответы о потребности, пользователях и данных. Каждый ответ можно направить в нужное поле. Перехожу к карточке: все сведения доступны для редактирования, тему и название добавляю вручную. Сначала сохраняю черновик. Рейтинг равен нулю, потому что сведения ещё не подтверждены. Теперь проверяю шесть заполненных полей, отмечаю подтверждение и пересчитываю. Получаем пятьдесят баллов; расшифровка показывает вклад каждой группы и недостающие сведения. Передаю эту карточку участнику два: он дополнит её, покажет оставшиеся баллы и публикацию.

## Передача участнику 2

Оставьте открытой карточку **«Демо: очередь в кафе»** с сохранёнными шестью подтверждениями и рейтингом **50/100**. Фраза перехода: **«Пятьдесят баллов уже есть. Покажем, каких сведений не хватает для ста и что именно увидит команда после публикации»**.

Участник 2 дополняет следующие шесть полей, подтверждает их, нажимает **«Сохранить и пересчитать»**, показывает **100/100**, затем **«Опубликовать задачу»**.

| Оставшееся поле | Готовое значение | Вклад после подтверждения |
|---|---|---|
| Ограничения | Веб-прототип за две недели; без подключения оплаты и без персональных данных | +10 |
| Ожидаемый результат | Веб-прототип предзаказа обедов и короткая инструкция для кассира | +15 |
| Критерии успеха | В тестовом сценарии среднее ожидание заказа ниже на 20% | +15 |
| Контакт | Демо-менеджер кафе | Вместе с двумя строками ниже: +10 |
| Формат взаимодействия | Созвон по вторникам на 15 минут | Часть группы «Связь с бизнесом» |
| Обратная связь | Демо-менеджер даёт комментарии к прототипу в течение двух рабочих дней | Часть группы «Связь с бизнесом» |

Таким образом, участник 2 добавляет оставшиеся **50 баллов**. Для начисления баллов за связь должны быть заполнены и подтверждены все три поля этой группы.

## Если демонстрация отклонилась от сценария

- Если вместо трёх ожидаемых полей показаны другие вопросы, проверьте связь с сервером и режим в отдельном `.env`. Не подменяйте третий ответ данными, пока его поле назначения не установлено в **«Данные»**.
- Если после сохранения рейтинг остаётся 0, проверьте шесть отметок и нажмите **«Сохранить и пересчитать»**. Одно сохранение черновика не подтверждает поля.
- Если недоступен сервер, введённый текст остаётся в форме. Восстановите сервер с тем же `.env` и повторите действие; локальная резервная форма не сохраняет карточку в базу без API.
