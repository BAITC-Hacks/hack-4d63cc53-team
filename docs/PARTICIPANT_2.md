# Участник 2: серверная часть

Статус: серверное ядро реализовано; 15 целевых автоматических тестов прошли. Подключены серверные маршруты marketplace и раздача frontend с того же адреса. Карта папок и владельцев — в разделе 4 DEVELOPMENT_PLAN.md.

## Модули

- `backend/app.py` — фабрика FastAPI и маршруты.
- `backend/schemas.py` — строгая валидация HTTP-тел.
- `backend/db.py` — SQLite-репозиторий и опубликованные снимки.
- `backend/tasks.py` — жизненный цикл черновика.
- `backend/scoring.py` — чистый расчёт рейтинга.
- `backend/ai.py` — OpenAI Responses и fallback.

## Запуск

### Docker: запуск с сохранением зависимостей

Установите и запустите Docker Desktop с Linux-контейнерами. Локальный Python и `.venv` для этого способа не нужны. Команды выполняются из корня репозитория.

Первый запуск и обновление после изменений кода:

```powershell
docker compose up -d --build
```

Откройте `http://127.0.0.1:8000/`. Если ранее запускали `start.bat` или Uvicorn вручную, сначала остановите тот сервер через `Ctrl+C`, чтобы освободить порт 8000.

Повторный запуск уже собранного проекта:

```powershell
docker compose up -d
```

Python-образ и пакеты скачиваются при первой сборке. Установка зависимостей выделена в отдельный слой перед копированием исходников: изменение кода сохраняет этот слой в кэше. Изменение `backend/requirements.txt`, базового образа или очистка кэша может потребовать загрузки пакетов снова. Это соответствует [рекомендациям Docker по кэшу сборки](https://docs.docker.com/build/cache/optimize/).

Сервер и frontend находятся в одном контейнере. Код копируется при сборке: после новых Git-изменений используйте команду с `--build`. Существующий локальный `.env` используется Compose для `OPENAI_API_KEY` и `OPENAI_MODEL`; он не попадает в образ. Если `.env` или ключ отсутствует, приложение работает в резервном AI-режиме. После изменения ключа повторите `docker compose up -d`, чтобы Compose обновил конфигурацию контейнера.

SQLite хранится в именованном Docker-томе по пути `/app/backend/runtime/app.sqlite3`. Контейнерная база отдельная от локальной `backend/runtime/app.sqlite3`; старые локальные записи автоматически не переносятся. Обычная остановка и пересборка сохраняют том. Команда `docker compose down -v` удаляет его вместе с данными — для обычной остановки она не нужна.

Полезные команды:

```powershell
docker compose ps
docker compose logs -f app
docker compose stop
```

`Dockerfile`, `compose.yaml` и `.dockerignore` поддерживает участник 2. `.dockerignore` исключает ключи, локальные окружения, Git и SQLite-файлы из контекста сборки. Демоданные автоматически не добавляются, браузер открывается вручную по указанному адресу.

Проверено 23.09.2026: `docker compose config --quiet` завершился успешно; `docker compose build` собрал образ, а повторная сборка показала `CACHED` для установки зависимостей и копирования исходников. Контейнер и сценарии приложения в этом проходе не запускались.

### Windows: запуск двойным щелчком

В корне проекта откройте `start.bat`. Нужен установленный Python 3.10 или новее (рекомендуется 3.13); если он не найден, скрипт покажет инструкцию установки. При первом запуске нужен интернет для загрузки Python-зависимостей.

Скрипт создаёт локальное окружение `.venv`, устанавливает зависимости из `backend/requirements.txt`, создаёт `.env` из `.env.example` только при отсутствии файла, запускает сервер и после его готовности открывает `http://127.0.0.1:8000/` в браузере. При повторном запуске окружение используется снова, а уже установленные подходящие версии пакетов сохраняются.

Для реального AI добавьте `OPENAI_API_KEY` в локальный `.env` и перезапустите скрипт. Существующий `.env` не перезаписывается. Без ключа доступен резервный режим. Демо-данные автоматически не загружаются; используется настроенная SQLite-база.

Окно запуска показывает логи сервера; для остановки нажмите `Ctrl+C`. Если порт 8000 занят, скрипт сообщит об этом: остановите предыдущий сервер в его окне и повторите запуск. Для работы на другом компьютере передайте изменения через обычный процесс команды; `.env` и `.venv` остаются локальными.

Запуск через BAT добавлен без отдельного прогона установки и сервера; приведённые ниже результаты прежних проверок относятся к ручному запуску.

### Ручной запуск

Создайте `.env` из `.env.example`, добавьте `OPENAI_API_KEY` только в локальный файл, затем выполните:

```powershell
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --reload
```

Документация доступна по `http://127.0.0.1:8000/docs`. SQLite по умолчанию хранится в `backend/runtime/app.sqlite3`. CORS разрешает локальные адреса frontend-разработки и меняется переменной `CORS_ORIGINS`.

## Контракт API

Редактируемые поля: `topic`, `title`, `context`, `need`, `users`, `data`, `constraints`, `expectedResult`, `successCriteria`, `contact`, `interactionFormat`, `feedbackProcess`.

- `POST /api/tasks`: `{"rawDescription":"...","fields":{"topic":"..."}}` создаёт черновик.
- `GET /api/tasks` и `GET /api/tasks/{id}` возвращают карточку с редактируемыми полями на верхнем уровне: `id`, `rawDescription`, `revision`, все поля, `confirmedFields`, `score`, `scoreBreakdown`, `missingFields`, `readiness`, `publicationStatus`, `publishedVersion`.
- `PATCH /api/tasks/{id}`: `{"expectedRevision":1,"fields":{"need":"..."}}`. Изменение поля снимает только его подтверждение.
- `POST /api/tasks/{id}/confirm`: `{"expectedRevision":2,"fields":["need","context"]}`.
- `POST /api/tasks/{id}/publish`: `{"expectedRevision":3}`.
- `POST /api/analyze`: `{"description":"...","answers":{"need":"..."}}` возвращает `fields`, минимум три `questions`, `missingFields`, `mode`, `reason`.

Все изменяющие запросы требуют целочисленный `expectedRevision`. При конфликте сервер возвращает `409` и текущую карточку в `detail.task`.

`publishedVersion` — независимый публичный снимок: `taskId`, `version`, `publishedAt`, вложенные `fields`, `confirmedFields`, `score`, `scoreBreakdown`, `missingFields`, `readiness`. В `fields` снимка остаются только подтверждённые значения. Низкий балл не блокирует публикацию.

Пример PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/tasks -Method Post -ContentType 'application/json' -Body '{"rawDescription":"Нужно улучшить запись клиентов"}'
```

## Оценка

Сервер считает подтверждённые непустые поля в семи группах на 100 баллов: контекст и потребность 20, данные 20, результат 15, критерии 15, ограничения 10, пользователи 10, связь с бизнесом 10. Уровни: `draft` 0–39, `working` 40–69, `ready` 70–89, `priority` 90–100.

## Интеграция участника 3

Каталог участника 3 принадлежит `backend/marketplace/**` и `frontend/marketplace/**`. Он читает `TaskRepository.list_published_tasks() -> list[dict]`; `taskId` служит идентификатором карточки, а вложенный `fields` — публичными данными. `backend/marketplace/router.py` уже подключён в `backend/app.py`, а `MarketplaceRepository` инициализируется с той же SQLite-базой и доступен в `request.app.state.marketplace_repository`. ## OpenAI

Адаптер вызывает `POST https://api.openai.com/v1/responses`, использует `OPENAI_MODEL` (по умолчанию `gpt-4.1-mini`), `store:false`, строгую JSON Schema и таймаут 15 секунд. Промпт требует оставлять неизвестные значения пустыми и не придумывать контакты, сроки, метрики или источники. Сервер проверяет структуру ответа; достоверность предложенного текста подтверждает человек. Результат анализа требует ручного подтверждения и не сохраняется автоматически. При отсутствии ключа, ошибке сети, таймауте или неверном ответе возвращается `fallback`, сохраняющий введённые значения и дающий три разных вопроса.
