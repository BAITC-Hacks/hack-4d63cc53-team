# HackAlem Task Marketplace

MVP помогает бизнесу превратить неполное описание проблемы в подтверждённую задачу, а студенческим командам — найти её и предложить решение. Цепочка: **описание → уточняющие вопросы → редактирование → подтверждение и рейтинг → публикация → отклики → ручной выбор → подтверждённый этап**.

Геймификация поощряет полноту сведений от бизнеса. Рейтинг прозрачно рассчитывается сервером; баллы команды за выполненный этап учитываются отдельно. AI предлагает вопросы и поля, окончательное содержание подтверждает человек.

## Текущее состояние

Основной интерфейс: **http://127.0.0.1:8000/**. Автономная демонстрация marketplace: **http://127.0.0.1:8000/marketplace/demo.html**. API: http://127.0.0.1:8000/docs.

## Запуск

Команды выполняются из корня репозитория. Нужен Python 3.10+; текущие проверки прошли с Python 3.12 из `.venv`. Node.js нужен только для JS-проверок; сборка frontend не требуется.

### Windows

Запустите `start.bat` двойным щелчком или командой `.\start.bat`. Скрипт находит Python через `py -3` или `python`, создаёт отсутствующую `.venv`, создаёт `.env` **только при его отсутствии**, устанавливает зависимости и запускает `backend.launch`. Launcher резервирует порт 8000 и открывает основной интерфейс после успешного `/api/health`. При занятом порте показывает ошибку. Остановка — `Ctrl+C`; первая установка зависимостей требует сети.

Ручной вариант PowerShell:

```powershell
if (-not (Test-Path .venv\Scripts\python.exe)) { py -3 -m venv .venv }
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Откройте основной адрес вручную. Вместо последней команды можно использовать `.\.venv\Scripts\python.exe -m backend.launch` для открытия браузера. Не запускайте оба сервера одновременно. Для разработки Uvicorn допускает `--reload`.

### Docker

При запущенном Docker Desktop с Linux-контейнерами:

```powershell
docker compose up -d --build
docker compose logs -f app
```

Адрес тот же; порт 8000 должен быть свободен. Повторный запуск без изменения кода — `docker compose up -d`, остановка — `docker compose stop`. SQLite хранится в именованном томе `app_runtime`, отдельно от локальной базы; демоданные автоматически не загружаются. Обычная остановка/пересборка сохраняет том. В предыдущем проходе участника 2 проверены Compose-конфигурация и сборка с кэшем; запуск контейнера в текущую приёмку не входит. Подробнее — [инструкция участника 2](docs/PARTICIPANT_2.md).

### Настройки

| Переменная | Назначение |
|---|---|
| `DATABASE_PATH` | SQLite-файл; по умолчанию `backend/runtime/app.sqlite3` |
| `AI_MODE` | `auto` по умолчанию или `fallback` для явного локального режима |
| `OPENAI_API_KEY` | Ключ только на сервере, в локальном `.env` или окружении |
| `OPENAI_MODEL` | Модель адаптера; значение в коде по умолчанию — `gpt-4.1-mini` |
| `CORS_ORIGINS` | Разрешённые origin через запятую для отдельного frontend |

Переменные процесса имеют приоритет над `.env`. Для локального демо без внешнего запроса задайте перед запуском `$env:AI_MODE = 'fallback'`. Compose передаёт ключ, модель и собственный путь БД; `AI_MODE` отдельно в `compose.yaml` не проброшена. Без ключа контейнер также использует fallback.

## Демоданные и восстановление демо

Набор — `data/marketplace-seed.json`, загрузчик — `data/seed_demo.py`. Он создаёт задачи через обычный core-сервис, подтверждает поля, вычисляет баллы и публикует снимки, затем связывает команды и отклики по фактическим новым ID. AI не вызывается.

Для воспроизводимой демонстрации создайте **новую** базу и запустите сервер с тем же путём:

```powershell
.\.venv\Scripts\python.exe -m data.seed_demo --database backend/runtime/demo-new.sqlite3
$env:DATABASE_PATH = 'backend/runtime/demo-new.sqlite3'
$env:AI_MODE = 'fallback'
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

При активированном окружении: `python -m data.seed_demo --database backend/runtime/demo-new.sqlite3`. Запускать следует модулем из корня, не командой `python data/seed_demo.py`.

Если файл существует, `--database` откажет и сохранит его содержимое. Для повторной репетиции выберите новый путь, например `backend/runtime/demo-rehearsal-2.sqlite3`, и задайте его в `DATABASE_PATH` нового серверного процесса. Старую базу удалять не нужно. Уже работающий сервер не переключает базу при изменении переменной в другом терминале.

Команда без параметра `python -m data.seed_demo` **добавляет** новый набор в настроенную БД при каждом запуске; это не сброс. Все 12 ключей карточки присутствуют, неизвестные значения пустые.

| Тема / задача | Балл core | Уровень |
|---|---:|---|
| Кафе — очереди в обед | 0 | `draft` |
| Магазин — аналитика возвратов | 40 | `working` |
| Склад — проверка комплектации | 70 | `ready` |
| Образование — запись на консультации | 90 | `priority` |
| Сервис — маршрутизация обращений | 100 | `priority` |

Набор содержит 5 исходных описаний/карточек, 5 команд и 5 откликов: один выбран, четыре ожидают решения. Этапы не предсоздаются. Контакты и ссылки `example.com` синтетические.

## Архитектура и рейтинг

Frontend — HTML/CSS и JavaScript ES modules. FastAPI раздаёт `frontend/` и `/api` с одного адреса. SQLite хранит задачи и отдельные таблицы marketplace. Зависимости зафиксированы в `backend/requirements.txt`.

| Часть | Файлы | Владелец |
|---|---|---|
| Оболочка, бизнес-сценарий, HTTP-клиент | Entry-файлы `frontend/`, `frontend/business/`, `frontend/shared/` | 1 |
| API, схема, версии, хранилище, рейтинг, AI | `backend/app.py`, `schemas.py`, `db.py`, `tasks.py`, `scoring.py`, `ai.py` | 2 |
| Каталог, команды, отклики, этапы, демо | `frontend/marketplace/`, `backend/marketplace/`, `data/`, тесты marketplace и README | 3 |

Редактирование снимает подтверждение только изменённых полей. Баллы рабочего состояния пересчитываются сервером; последняя публичная версия остаётся прежней до отдельной публикации. Публикация копирует только подтверждённые значения, остальные значения снимка пустые. Каталог читает снимки через `TaskRepository.list_published_tasks()`, не рабочие черновики.

`score = сумма весов полностью заполненных и подтверждённых групп`, максимум 100. Пробелы не считаются заполнением; группа получает весь вес либо 0.

| Группа | Поля | Вес |
|---|---|---:|
| Контекст и потребность | `context`, `need` | 20 |
| Данные | `data` | 20 |
| Результат | `expectedResult` | 15 |
| Критерии успеха | `successCriteria` | 15 |
| Ограничения | `constraints` | 10 |
| Пользователи | `users` | 10 |
| Связь с бизнесом | `contact`, `interactionFormat`, `feedbackProcess` | 10 |

`topic` и `title` не добавляют баллов, но требуют подтверждения для публичного отображения. Они могут присутствовать в `missingFields`. Расшифровка групп содержит `label`, `fields`, `points`, `maxPoints`, `reason`.

Уровни: 0–39 — `draft` («Черновик»), 40–69 — `working` («Рабочая»), 70–89 — `ready` («Готовая»), 90–100 — `priority` («Приоритетная»). Уровень `draft` не равен отсутствию публикации: опубликованная задача с 0 баллами доступна всем и принимает отклики. Формула проверяет заполнение и подтверждение, содержательность оценивает человек.

Каталог сортируется по убыванию баллов, при равенстве — по `taskId`. `topic` ищет подстроку без учёта регистра; `readiness` принимает один из четырёх кодов. Бизнес выбирает одну, несколько или ни одной команды, может отклонять отклики. Автоматического назначения и лимита откликов нет.

Подтверждение этапа выбранной команды добавляет **10 `progressPoints` один раз на этот этап**. Повтор возвращает `awarded: false`; начисление защищено SQLite-транзакцией. До выбора команды подтверждение даёт `409`. Баллы команды не изменяют рейтинг задачи; отклик сам по себе баллов не даёт.

## AI и резервный режим

`backend/ai.py` вызывает OpenAI Responses с JSON Schema, `store: false`, таймаутом 15 секунд. Промпт требует считать пользовательский текст данными, оставлять неизвестное пустым, не выдумывать контакты/сроки/метрики/источники и возвращать минимум три разных вопроса на русском. Вход: `description`, `answers`; выход: `fields`, `questions`, `missingFields`, `mode`, `reason`.

Адаптер проверяет завершённость, JSON, точные ключи/типы, все 12 полей, длины и минимум три непустых уникальных вопроса. Анализ сам по себе не сохраняет и не подтверждает задачу. При `AI_MODE=fallback`, отсутствии ключа, сетевой ошибке, таймауте или неверном ответе возвращает `mode: "fallback"` и причину. Локальный режим сохраняет ответы, переносит описание в пустой `context` и задаёт три шаблонных вопроса по пропускам либо уточнениям. В текущем проходе реальный AI не вызывался.

## HTTP-контракты

Полная схема — `/docs` и `/openapi.json`. Лишние поля тела запрещены. Создание возвращает `201`, чтение/изменения — `200`, отсутствующие сущности — `404`, неверные тела — `422`.

| Метод и путь | Назначение / тело |
|---|---|
| `GET /api/health` | `{"status":"ok"}` |
| `POST /api/analyze` | `{"description":"Хотим сократить очереди","answers":{"need":"Сократить ожидание"}}` |
| `GET /api/tasks`, `GET /api/tasks/{id}` | Рабочие задачи: `id`, поля верхнего уровня, `revision`, подтверждения, рейтинг, `publishedVersion` |
| `POST /api/tasks` | `rawDescription`, объект `fields` |
| `PATCH /api/tasks/{id}` | `{"expectedRevision":1,"fields":{"need":"Сократить ожидание"}}` |
| `POST /api/tasks/{id}/confirm` | `{"expectedRevision":2,"fields":["context","need"]}` |
| `POST /api/tasks/{id}/publish` | `{"expectedRevision":3}` |
| `GET /api/catalog?topic=кафе&readiness=draft` | Массив публичных снимков; фильтры необязательны |
| `GET /api/teams`, `POST /api/teams` | Список / создание команды |
| `POST /api/proposals`, `GET /api/tasks/{id}/proposals` | Создание / список откликов с вложенным профилем `team` |
| `PATCH /api/proposals/{id}` | `{"status":"selected"}` или `{"status":"rejected"}` |
| `POST /api/milestones`, `GET /api/tasks/{id}/milestones` | Создание / сохранённые этапы с вложенным `team` |
| `POST /api/milestones/{id}/confirm` | Без тела; ответ содержит `milestone` и `awarded` |

Только изменение/подтверждение/публикация задачи требуют актуальный `expectedRevision`; конфликт даёт `409` и текущую задачу в `detail.task`. Номера берите из последнего ответа. Публичный снимок имеет `taskId`, `version`, `publishedAt`, вложенные `fields`, `confirmedFields`, `score`, `scoreBreakdown`, `missingFields`, `readiness`.

Пример создания карточки со всеми редактируемыми полями, пригодный для демонстрации кафе:

```json
{
  "rawDescription": "Хотим сократить очереди в кафе",
  "fields": {
    "topic": "кафе", "title": "Предзаказ обедов",
    "context": "В будни с 12:00 до 14:00 гости ждут у кассы",
    "need": "Сократить ожидание заказа", "users": "Гости кафе и кассиры",
    "data": "Обезличенные времена заказа и выдачи за две недели",
    "constraints": "Веб-прототип за две недели, без интеграции с оплатой",
    "expectedResult": "Прототип предзаказа и отчёт о пилоте",
    "successCriteria": "На тестовой выборке среднее ожидание ниже на 20%",
    "contact": "Демо-менеджер кафе", "interactionFormat": "Созвон по вторникам на 15 минут",
    "feedbackProcess": "Менеджер проверяет прототип и отвечает в течение двух дней"
  }
}
```

Создание команды, отклика и этапа — три отдельные JSON-тела для соответствующих POST. Замените `TASK_ID`/`TEAM_ID` фактическими ID из ответов.

```json
{"name":"Flow Makers Demo","interests":["сервисы для кафе"],"skills":["UX","JavaScript"],"technologies":["HTML","CSS"]}
```
```json
{"taskId":"TASK_ID","teamId":"TEAM_ID","idea":"Экран предзаказа обедов для гостей","plan":"Интервью, макет, тестирование на пяти гостях","deadline":"2 недели","prototypeUrl":"https://example.com/cafe-prototype"}
```
```json
{"taskId":"TASK_ID","teamId":"TEAM_ID","description":"Проверен прототип предзаказа","evidence":"https://example.com/cafe-pilot-report"}
```

Команда получает `id`, `createdAt`, `progressPoints: 0`; имя — 2–120 символов, interests/skills — непустые списки непустых строк. Отклик получает `id`, `createdAt`, `status: "pending"`; идея/план — минимум 10 символов, срок — 2; URL — HTTP(S), `null` или отсутствует. Этап получает `id`, `createdAt`, `confirmedAt: null`, `pointsAwarded: 0`; описание — минимум 5 символов, evidence — 3 (текст или ссылка). Длины проверяются после обрезки пробелов. Подтверждённый этап имеет время в `confirmedAt` и `pointsAwarded: 10`; отдельного поля `confirmed` нет.

### Интеграция экранов участником 1

`frontend/marketplace/marketplace.js` возвращает DOM-элементы через пять экспортов:

| Экспорт | Вход |
|---|---|
| `createCatalogScreen({ onOpenTask })` | callback получает публичный снимок |
| `createTeamsScreen({ onCreated })` | callback получает команду |
| `createProposalScreen(task, { onSubmitted, teamId })` | Снимок, текущая команда, callback после отправки |
| `createProposalReviewScreen(task, { onChanged })` | Снимок, callback после решения |
| `createMilestoneScreen(task, { onCreated, onConfirmed })` | Снимок, callbacks после создания/подтверждения |

Передавайте снимок с `taskId` и вложенным `fields` из каталога или `publishedVersion`, не рабочую задачу с `id`. Подключите `/marketplace/marketplace.css`; готовый пример — `demo.html`/`demo.js`. Все запросы используют `request` из `frontend/shared/api.js`: путь **без `/api`**, например `request('/teams')`; `body` — объект, сериализацию выполняет клиент. Демо до импорта модулей задаёт `window.API_BASE = location.origin + '/api'`; это также нужно для использования другого порта.

## Сценарий защиты до 5 минут

До выступления создайте отдельную демо-БД и откройте основной экран и marketplace в двух вкладках. Проверьте пять баллов и режим AI. Пока общая навигация не интегрирована, переход во вторую вкладку нужно обозначить жюри. Для выбора нескольких команд заранее добавьте ещё два отклика разных команд **на исходную задачу кафе**: seed уже содержит один отклик на неё.

| Время | Кто | Действия |
|---|---|---|
| 0:00–0:30 | 1 | Ввести «Хотим сократить очереди в кафе»; объяснить нехватку данных и критериев |
| 0:30–1:30 | 1 | Показать три вопроса и режим AI, вставить ответы, отредактировать и подтвердить карточку |
| 1:30–2:30 | 2 | Показать веса и рост рейтинга; изменить поле, показать снятие подтверждения, подтвердить и опубликовать |
| 2:30–3:30 | 3 | В marketplace выбрать роль «Команда», фильтр кафе/`draft`; задача с 0 доступна. Выбрать команду и отправить отклик |
| 3:30–4:30 | 3 | Переключиться на «Бизнес», выбрать два отклика разных команд, отклонить третий. Создать/подтвердить этап выбранной команды, показать +10 и сохранение после перезагрузки |
| 4:30–5:00 | 2 | Показать режим AI, промпт/JSON, защиту от повторного начисления; назвать запуск и ограничения |

Готовые ответы кафе: **кто/когда** — гости и кассиры, будни 12:00–14:00; **данные** — обезличенные времена заказов за две недели; **критерий** — ожидание ниже на 20%; **результат/границы** — веб-прототип за две недели без оплаты; **связь** — демо-менеджер, созвон по вторникам, ответ за два дня. Полная карточка и тела отклика/этапа приведены выше.

После перезагрузки откройте «Этапы» и «Команды»: статус и +10 должны сохраниться. UI блокирует повторное подтверждение; повторный HTTP-запрос возвращает `awarded: false`, рейтинг задачи не меняется. Материалы для сдачи: исходники, README, seed JSON/CLI и этот сценарий. Репетиция с таймером и чистый запуск другим участником ещё предстоят.
